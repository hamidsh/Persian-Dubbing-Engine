# راهنمای نصب و اولین دوبله

## ۱. ترتیب نصب

Python 3.11 x64 و Git و FFmpeg باید در PATH باشند. نصب پایه با `install.bat`، مدل اصلی با `scripts/setup_moss.ps1` و اجرا با `run.bat` است. نیازی به فعال‌کردن Conda یا venv دستی نیست. نصب workerها را از ریشه همین پروژه انجام دهید. تمام اسکریپت‌ها پس از خطای نصب متوقف می‌شوند.

- `.venv`: رابط، ASR روی CPU، ذخیره، میکس، HTTP و تست.
- `.venv-moss`: PyTorch CUDA 12.8، MOSS، Transformers 5 و PEFT.
- `.venv-seed`: اختیاری؛ stack مستقل مطابق Seed-VC با Torch 2.4 / CUDA 12.4 و Transformers 4.46.
- `.venv-diarization`: اختیاری؛ pyannote 4 روی CPU.

نسخه کد بالادستی MOSS و Seed در اسکریپت نصب به commit مشخص متصل شده است. نصب‌کننده checkout موجود با revision دیگر را تغییر نمی‌دهد. اگر محیط‌ها از قبل وجود داشته باشند، pip ممکن است بسته‌هایشان را به نسخه‌های مشخص‌شده تغییر دهد؛ این پوشه‌ها مختص همین برنامه باشند.

مدل‌ها در cache معمول Hugging Face دانلود می‌شوند؛ برای انتقال cache پیش از اجرا `HF_HOME` را تعیین کنید. `config.local.json` مسیر Python و کد مدل‌ها را نگه می‌دارد و در Git نادیده گرفته می‌شود. تنظیمات هر پروژه در SQLite هم ذخیره می‌شود؛ پس از نصب جدید یک پروژه جدید بسازید یا تنظیمات پروژه قدیمی را اصلاح کنید.

## ۲. اولین آزمایش صدا — قبل از دوبله کامل

1. `run.bat` → پروژه جدید / بازکردن → یک پوشه خالی.
2. پنل گویندگان → افزودن صدای فارسی. مرجع ۱۰ تا ۳۰ ثانیه‌ای تمیز، تک‌گوینده و بدون موسیقی مناسب شروع آزمایش است؛ کیفیت واقعی را با شنیدن بسنجید.
3. پنل آزمایش → متن کوتاه → فقط «مرجع فارسی» → ساخت نمونه.
4. بعد از تولید، نمونه را انتخاب و پخش کنید. طبیعی‌بودن و شباهت دو معیار جدا هستند.
5. اگر خوب بود، نمونه انگلیسی هدف را برای همان صدا اضافه کنید و روش‌های دیگر را آزمایش کنید.

نمونه‌های متنوع در `examples/benchmark.fa.json` هستند. اگر فارسی ضعیف بود ابتدا متن و مرجع را بررسی کنید؛ سیستم به‌طور مخفی مدل یا صدا را عوض نمی‌کند. `diagnostic` تنها گزینه تست فنی بوق است و نباید برای دوبله انتخاب شود.

## ۳. Seed-VC و Anchor

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup_seed.ps1
```

مرجع فارسی Source و نمونه اصلی انگلیسی Target است. «ساخت Anchor» یک فایل کاندیدا می‌سازد؛ QC فنی فقط سکوت، طول و clipping را بررسی می‌کند و جای شنیدن را نمی‌گیرد. Anchor را بشنوید و سپس «تأیید شنیداری» را بزنید. برای استفاده در دوبله، `route` تنظیمات را `anchor` کنید.

- `native`: مرجع فارسی اصلی، پیش‌فرض.
- `anchor`: فقط Anchor تأییدشده؛ نبود تأیید خطا می‌دهد.
- `direct`: مرجع انگلیسی مستقیم، برای مقایسه نشت لهجه.
- `post_vc`: تولید با مرجع فارسی و سپس تبدیل هر جمله.

شکست تبدیل، صدای تأییدشده را تغییر نمی‌دهد؛ مسیر native همچنان قابل انتخاب است. Anchor آزمایشی A/B به بانک پروژه اعمال نمی‌شود. هنگام تغییر target، تأیید Anchor باطل می‌شود.

## ۴. مترجم محلی llama.cpp

یک مدل GGUF سازگار با llama.cpp (برای مثال خانواده Qwen مناسب فارسی) جداگانه دریافت کنید. مدل و quantization در این پروژه تحمیل نشده‌اند. ابتدا آن را روی CPU اجرا کنید تا هم‌زمان با MOSS حافظه GPU را اشغال نکند:

```powershell
llama-server.exe -m D:\Models\translator.gguf --host 127.0.0.1 --port 8080 -ngl 0 -c 8192
```

نشانی پیش‌فرض `http://127.0.0.1:8080/v1/chat/completions` است. اگر سرور model alias می‌خواهد، `translator_model` را در تنظیمات مطابق آن قرار دهید. اگر API key لازم است، از متغیر محیطی `PDE_TRANSLATOR_KEY` استفاده کنید؛ آن را در فایل پروژه ننویسید.

سرویس باید `response_format=json_object` را پشتیبانی کند. برنامه JSON معتبر و وجود متن فارسی را بررسی می‌کند؛ پاسخ خراب به‌عنوان ترجمه ذخیره نمی‌شود. رد JSON یا timeout در log دیده می‌شود. ترجمه‌های موجود خودکار بازنویسی نمی‌شوند؛ برای ترجمه دوباره متن فارسی همان ردیف را پاک کنید. CLI گزینه `translate --force` هم دارد.

بدون سرویس مترجم: یک SRT فارسی وارد کنید یا متن فارسی را در جدول بنویسید.

## ۵. ویدئو، متن و گوینده

ویدئو را وارد کنید؛ فایل اصلی کپی نمی‌شود، بنابراین محلش را ثابت نگه دارید. یک پروژه برای یک فایل است. Whisper نخستین بار مدل را دانلود می‌کند. ASR پیش‌فرض CPU/int8 است. وزن ASR از config قابل تغییر است؛ خطای دانلود/نام مدل به‌صورت مستقیم گزارش می‌شود.

اگر گوینده‌ها مشخص‌اند، شناسه‌هایی مانند `speaker_01` و `speaker_02` را در جدول وارد کنید. SRT می‌تواند ابتدای متن هر cue برچسب `[speaker_01]` داشته باشد؛ نمونه در `examples/sample.fa.srt` موجود است.

تفکیک خودکار اختیاری:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup_diarization.ps1
$env:HF_TOKEN='your_token'
.\run.bat
```

قبل از آن شرایط مدل `pyannote/speaker-diarization-community-1` در Hugging Face را بپذیرید. قطعه شامل چند گوینده علامت‌گذاری می‌شود؛ خروجی این نسخه جداسازی کلمات هم‌زمان دو نفر نیست. برای اصلاح، ردیف‌ها را به جمله‌های جدا با زمان و گوینده مناسب تبدیل کنید.

پنل گویندگان → صدای فارسی هر شناسه → ذخیره تخصیص. دو گوینده می‌توانند عمداً یک صدا داشته باشند؛ برنامه فعلاً انتخاب خودکار شباهت یا تضمین تمایز ندارد.

## ۶. تلفظ و زمان‌بندی

ترتیب: **تلفظ دستی کل جمله → واژه‌نامه config → نرمال‌سازی → TTS**. واژه‌نامه در `dictionary` تنظیمات یک JSON mapping است، مثلاً `{"OpenAI":"اوپن اِی آی"}`. تلفظ دستی دست‌نخورده به مدل می‌رود و باید خودتان اعداد آن را نیز اصلاح کنید.

هم‌نگاره‌ها علامت می‌خورند و معنای آنها حدس زده نمی‌شود. تاریخ‌ها و ساعت‌ها هنوز خوانش معنایی کامل ندارند؛ برای آنها تلفظ دستی بنویسید. IPA به MOSS ارسال نمی‌شود. emotion پیشنهادی مترجم ثبت می‌شود اما کنترل واقعی احساس در این adapter فعال نیست.

بعد از تغییر متن، مرجع یا تنظیمات، تولید را دوباره بزنید؛ cache از بازاستفاده خروجی قدیمی جلوگیری می‌کند. مدت بلندتر حداکثر تا `max_speedup=1.15` با Rubber Band فشرده می‌شود؛ اگر FFmpeg این فیلتر را ندارد خطا می‌دهد. برای خروجی طولانی‌تر، ترجمه را کوتاه یا زمان پایان را اصلاح کنید. خروجی نهایی کلمات را قطع نمی‌کند.

## ۷. خروجی

«ساخت خروجی نهایی» یک پوشه جدید در `exports/` می‌سازد، با:

- `dubbed.wav`: میکس فارسی.
- `speaker_01.wav` و ...: stem مستقل؛ نگاشت به شناسه‌ها در report.
- `subtitles.fa.srt` و `segments.json`.
- `report.json`: معیارها، هشدارها، limiter، نگاشت stem.
- `dubbed.mp4`: در صورت انتخاب گزینه ویدئو، H.264/AAC.

صدای انگلیسی اصلی خودکار به خروجی اضافه نمی‌شود. برای موسیقی/محیط از فایل جداشده مجزا استفاده کنید؛ واردکردن صوت اصلی به‌عنوان پس‌زمینه صدای انگلیسی را هم دوباره وارد میکس می‌کند. خروجی این نسخه mono است. پروژه SQLite، cache و referenceها را برای ادامه کار نگه دارید. جابه‌جایی پوشه پروژه، referenceهای داخلی را حفظ می‌کند؛ مسیر ویدئوی اصلی خارجی است.

## ۸. توقف و رفع خطا

دکمه توقف workerهای سنگین و فرزندانشان را می‌بندد. ASR و درخواست HTTP جاری ممکن است تا پایان فراخوانی فعلی/timeout منتظر بمانند. رابط در این مدت بسته نمی‌شود تا thread نیمه‌کاره نماند. متن‌ها مرحله‌ای ذخیره می‌شوند و WAVهای کامل قابل ادامه‌اند؛ فایل `.part.wav` هرگز cache معتبر نیست.

`pde doctor` مسیر FFmpeg، نصب ASR و منابع را نشان می‌دهد. `logs/moss.log` و `logs/diarization.log` خطاهای worker را دارند. برای خطای CUDA ابتدا driver و Python واقعی worker را بررسی کنید. ۱۶GB تضمین هم‌زمانی چند مدل نیست؛ سایر مدل‌های GPU و سرور ترجمه GPU را ببندید. برنامه فعلاً unload یک سرویس LLM خارجی را کنترل نمی‌کند.

در صورت خطای backend پخش Qt، فایل خروجی را با پلیر خودتان باز کنید. پخش Qt روی محیط توسعه بررسی شده؛ codec/driver سیستم مقصد ممکن است متفاوت باشد. برنامه هیچ تنظیم شبکه‌ای را تغییر نمی‌دهد.
